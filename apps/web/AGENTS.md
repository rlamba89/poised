# apps/web

A plain React single-page app: **React 19 + Vite + React Router + Mantine**. There's no server rendering; everything runs in the browser. It replaced Next.js in plan F2 (session S04, 12 Oct 2026).

- **Pages and URLs:** `src/routes.tsx` lists every URL and its page (`src/pages/…`). `src/routes.test.ts` pins each URL to its page, so add a case there when you add a route.
  - Each page's code is loaded when it's first opened (the route's `lazy`), so the patient's link doesn't download the editor.
  - The pages are thin: they read the URL's params and render a component from `src/features/…`, where the real UI lives.
  - A page is keyed by its URL params (e.g. `key={eid}`), so moving to another episode starts afresh.
- **Trusts and hospitals (S08):** a hospital's pages are under `/o/:orgId/h/:hospitalId/…`, inside `pages/hospital/HospitalLayout.tsx`. It reads `/api/me` (`src/lib/auth.tsx`) and gives every page `useHospital()`: the trust, the hospital, the user's role there and `base` (`/o/<trust>/h/<hospital>`). `base` starts both the page URLs and the API paths (`api(\`${base}/episodes\`)` calls `/api/o/…/h/…/episodes`). Check permissions with `atLeast(role, "super_clinician")` (the A-5 ladder). `/` is the hospital picker. The trust's **Staff** page (S09) is `…/staff` under the same layout, for whole-trust admins only (`canManageStaff(trust)`); its API is the trust route `/api/o/<trust>/staff`.
- **The platform admin's console (S10):** `/admin`, `/admin/trusts/new` and `/admin/trusts/:orgId`, inside `pages/admin/AdminLayout.tsx`, which refuses anyone whose `/api/me` isn't `platformAdmin`; the UI is in `src/features/admin/` and calls `/api/admin/…`. The trust's **Settings** page (`…/settings`, `src/features/settings/`) is for whole-trust admins (`canManageSettings`); it draws its fields from the setting definitions Go sends, so a new setting needs no TypeScript unless it's a new kind. The trust's **Audit** page (S11, `…/audit`, `src/features/audit/`) is for whole-trust admins (`canSeeAudit`); its filters live in the URL (`filters.ts`), and every load of the list is itself an audit row, so it fetches only when the filters are applied.
- **Patients (S13):** **New episode** is its own page, `…/episodes/new` (`src/features/episodes/NewEpisodePage.tsx`): a search of this hospital's patients (`GET …/patients?q=&dob=`, sent only once `searchQuery` in `newEpisode.ts` says the term is precise enough), or a new patient's details, then the episode. A 409 from Create is read by `conflictOf` (a mismatch, or a possible duplicate with Create anyway). A patient's page is `…/patients/:pid` (`PatientPage.tsx`): the trust's record and this hospital's episodes only. The identifier's label ("NHS number") comes from `nationalIdLabel()` (`GET /api/config`), never a literal.
- **The patient's side (S14):** the invite link is `/i/:token` (`src/features/patient/InviteLink.tsx`): **Continue** (a POST that returns only the hospital's name), then the date of birth (`dob.ts`), which sets the patient's session cookie and replaces the page with `/home/episodes/:eid`, their HQ (`PatientHQ.tsx`, on `/api/p/episodes/<id>`). A 401 there means the session ended (30 minutes idle). Staff fill in the same form on the patient's behalf at `…/episodes/:eid/patient-form` (PAT-09; `PatientHQ` with `onBehalf`). These patient pages sit outside the hospital layout: no staff sign-in. **`/qa/messages`** lists the captured texts and emails (MESSAGING=capture).
- **A returning patient (S15):** `/signin` (`Signin.tsx`) asks for a sign-in link by mobile or email; the link, `/s/:token`, is the same component as the invite (`InviteLink` with `kind="signin"`, API `/api/p/signin/<token>/…`) and lands on **`/home`** (`PatientHome.tsx`, `GET /api/p/home`): every trust's questionnaires, newest first, and the patient's contact details in part, with Change. A new mobile or email is confirmed at `/v/:token` (`ConfirmContact.tsx`). The patient's session is their **account's** (every trust's record of them), so `/home/episodes/:eid` opens any of them. `links.ts` says why a link stopped (locked, expired, unknown) and which pages are the patient's (`RouteError` never sends them to the staff sign-in).
- **Scheduled jobs (S16):** reminders and "not responding" run in Go (`internal/jobs`); the web app only shows them: a red **Not responding** badge on the episode page, and General notes entries whose author is **Automatic** (`event.automatic`). **`/qa/jobs`** (`src/features/qa/ScheduledJobs.tsx`, MESSAGING=capture only; open locally, a platform admin on QA since S12) runs the jobs as of a later time (`POST /api/qa/jobs/run`) and moves the local timer's clock ahead (`PUT /api/qa/jobs/clock`); its time helpers are `jobsTime.ts`.
- **Staff sign-in (S12):** `/login` (`pages/Login.tsx`) shows what `GET /api/config`'s `staffSignIn` says: **Sign in** for Cognito's managed login (AWS), and/or the dev login's user list (local). `src/lib/signin.ts` is the OAuth code flow with PKCE: `startSignIn` keeps a random verifier and state in `sessionStorage` and sends the browser to the managed login; `/auth/callback` (`pages/AuthCallback.tsx`) checks the state with `finishSignIn`, posts `{code, verifier}` to `POST /api/auth/callback` (Go exchanges it and sets the session cookie), then goes to `startPath`; a refusal goes back to `/login` with the API's message. **Every staff Sign out goes through `signOut`**, which also signs out of the managed login (its `/logout`, back to `/login`) where there's Cognito. The browser never holds a token. The testers' pages show "Sign in as a platform admin" when the API answers 401 (`features/qa/access.ts`).
- **Errors:** the root route's `ErrorBoundary` (`src/pages/RouteError.tsx`) catches a page that fails to load or crashes. If the page's code couldn't be downloaded (usually after a deploy), it reloads once (`src/lib/chunkError.ts`); otherwise it shows "Something went wrong" with Reload.
- **Navigation:** `useNavigate`, `useParams`, `useLocation` and `<Link to>` from `react-router`. With Mantine: `<Button component={Link} to={…}>`.
- **API:** `src/lib/api.ts` calls `/api/…` on the same origin. `vite.config.ts` proxies `/api` to the Go API (`API_URL`, default `http://localhost:8080`), in `vite` (dev) and in `vite preview`. On AWS, Amplify does the same with a rewrite (plan F4).
- **Types:** `tsconfig.json` is the browser code, with no Node types, so `process.env` in `src/` fails the type check. `tsconfig.node.json` covers `vite.config.ts`, which runs in Node.
- **Brand (20 Oct):** `src/theme.ts` is Mantine's theme: the teal `brand` colour is the primary one. `src/features/brand/Logo.tsx` is the logo (`<Logo />` inside a `Title` or `Text`, which sizes it; `inverse` on a teal background). The files are in `docs/brand/`.
- **Imports:** `@/…` is `src/…`. `@poised/clinical` is the workspace package's TypeScript source, which Vite compiles.
- **Scripts:** `npm run dev` (port 3000), `build` (type-check, then `dist/`), `preview` (serves `dist/` on port 3000), `lint` (`tsc` on both tsconfigs), `test` (Vitest).
- **Nothing country-specific in the code** (A-20): the region, domain, time zone, locale and phone country come from config.
  - `main.tsx` loads `GET /api/config` once (`src/lib/config.ts`) before the first page renders. Format every date with `src/lib/format.ts`, which uses that locale; never pass a locale such as `"en-GB"` yourself.
  - A Go test (`apps/api/internal/config/literals_test.go`) fails on a locale, time-zone or region literal in `src/`.
